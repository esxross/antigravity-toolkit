# code-review スキル

## レビュー手順

1. 変更ファイルを特定する（`git diff main...HEAD` または指定ファイル）
2. 以下の観点でレビューする：

### アーキテクチャ観点
- レイヤー境界の違反がないか（domain → infra は禁止）
- ユースケースが1責務に収まっているか
- 依存の方向が正しいか

### コード品質観点
- 型安全性が確保されているか（`any` の使用）
- エラーハンドリングが適切か
- 重複コードがないか

### セキュリティ観点
- ユーザー入力のバリデーションがあるか
- 認証・認可が適切に行われているか
- シークレットがコードに含まれていないか

### テスト観点
- 重要なパスにテストがあるか
- エッジケースが考慮されているか

## 出力フォーマット

```
## コードレビュー結果

### 必須修正（マージ前に対応）
- ...

### 推奨改善（できれば対応）
- ...

### 良い点
- ...
```
