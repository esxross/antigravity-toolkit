# テスト方針

## テストの種類と配置

| 種類 | 対象 | ツール | 配置 |
|-----|------|--------|------|
| ユニットテスト | domain・application | Vitest | `src/**/__tests__/` |
| インテグレーション | infra（DB） | Vitest + testcontainers | `src/infra/__tests__/` |
| E2E | API・UI全体 | Playwright | `e2e/` |

## 必須テスト
- ユースケースはすべてユニットテストを書く
- ドメインモデルのバリデーションロジックはテストを書く
- 外部API・DBはモックではなく実サービスを使う（インテグレーション）

## テストの書き方
```ts
describe("CreateUserUseCase", () => {
  it("正常系: 有効な入力でユーザーを作成できる", async () => { ... })
  it("異常系: メールアドレス重複でエラーを返す", async () => { ... })
  it("異常系: 無効なメールアドレス形式でエラーを返す", async () => { ... })
})
```

## モックの方針
- DBのモックは使わない（インテグレーションテストで実DB）
- 外部有料APIのみモック許可（Stripe, SendGrid等）
- ドメインサービスのモックは許可
