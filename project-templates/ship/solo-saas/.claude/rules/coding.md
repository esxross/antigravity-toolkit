# コーディングルール

## 基本方針
- シンプル第一：最小限のコードで要件を満たす
- 早期リターンでネストを浅く保つ
- 1関数1責務

## TypeScript
- `any` は使わない。不明な型は `unknown` を使う
- 型は推論できる場合は省略してよい
- `interface` より `type` を優先（拡張が不要な場合）

## React / Next.js
- Server Components をデフォルトにする
- `"use client"` は本当に必要な場合のみ
- データフェッチは Server Component 内で行う

## エラーハンドリング
- `try/catch` は非同期処理に必ずつける
- ユーザーへのエラーメッセージは具体的に
- console.error は残してよいが、本番ではログサービスに送る

## セキュリティ
- 環境変数は `.env.local`（`NEXT_PUBLIC_` なしは非公開）
- ユーザー入力は必ずバリデーション（zod 推奨）
- SQLクエリは必ずパラメータバインディング
