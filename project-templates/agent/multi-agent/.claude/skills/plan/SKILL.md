# plan スキル

## 目的
実装を開始する前に、並列開発が可能な形でタスクを分解する。

## 手順

### 1. 要件の確認
- 何を実装するか明確にする
- 影響するBC（境界コンテキスト）を特定する
- 既存コードを調査する（Glob・Grep使用）

### 2. インターフェース定義（Phase A）
並列実装の前に合意が必要なものを定義する：
- BCが公開するインターフェース
- 共有DTOの型定義
- APIエンドポイントの形

### 3. タスク分解（Phase B — 並列可能）
BC単位または責務単位でタスクに分ける。
各タスクは他のタスクに依存しない形にする。

### 4. task.md への書き出し

```markdown
## Phase A: インターフェース定義
- [ ] ...

## Phase B: 並列実装
- [ ] B1: [担当BC] — [内容]
- [ ] B2: [担当BC] — [内容]
- [ ] B3: [担当BC] — [内容]

## Phase C: 統合
- [ ] 統合テスト
- [ ] E2E確認
```

### 5. 確認
計画を提示してユーザーの承認を得てから実装を開始する。
