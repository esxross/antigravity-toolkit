# ループルール

## イテレーション完了の定義

イテレーションは以下が **すべて** 完了したときに「完了」とみなす：

1. 実装コードが書かれている
2. テストが通っている（`npm test` or `pytest` で確認）
3. `git commit` が完了している
4. `progress.json` が更新されている

**テストなしのコミットは禁止。**

## progress.json の更新ルール

```json
{
  "iteration": <前の値+1>,
  "status": "in_progress" | "done" | "blocked",
  "last_completed": ["完了したタスクを箇条書き"],
  "next_tasks": ["次イテレーションでやるべきタスク"],
  "blockers": ["人間の判断が必要な問題（空なら[]）"],
  "error_count": <エラーが起きたら+1>,
  "last_commit": "<git commit hashまたはメッセージ>",
  "updated_at": "<ISO 8601形式>"
}
```

## ステータスの意味

| status | 意味 | loop.sh の挙動 |
|--------|------|--------------|
| `not_started` | 未開始 | ループ継続 |
| `in_progress` | 作業中 | ループ継続 |
| `done` | 目標達成 | **ループ停止** |
| `blocked` | 人間の判断が必要 | **ループ停止** |

## 変更スコープ制限

- 1イテレーションで変更するファイルは **最大 10 ファイル** まで
- 大きな変更は複数イテレーションに分割する
- スコープを超えそうな場合は `next_tasks` に残して終了する

## コミットメッセージ規約

```
feat(iter-N): <実装内容の要約>
fix(iter-N): <修正内容>
```

例: `feat(iter-3): ユーザー認証のJWT検証を実装`

## 自己解決の手順

エラーが出たとき：
1. エラーメッセージをすべて読む
2. 関連ファイルを読んで原因を特定する
3. 修正して再テスト
4. 3回試みて解決しない場合は `blockers` に記録して終了
