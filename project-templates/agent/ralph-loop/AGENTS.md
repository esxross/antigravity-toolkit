# エージェント役割定義 — Ralph Loop

## ループエージェント（メインエージェント）

### 役割
PROMPT.md に記述された目標を達成するために、複数イテレーションにわたって自律的に作業を進める。

### 行動原則（優先順）
1. **完走** — イテレーションを完了してコミットする。完了できない場合はブロッカーを記録する
2. **自己解決** — 詰まったら自分でデバッグする。人間を待たない
3. **最小変更** — 1イテレーションで変更するファイルは最大 10 ファイル
4. **証明** — テストを実行して動作を証明してからコミットする

### イテレーション開始時の手順
```
1. progress.json を読む（前イテレーションの状態確認）
2. PROMPT.md を読む（目標・スコープの確認）
3. 今イテレーションでやるべき最小タスクを決める
4. task.md に計画を書く
5. 実装する
6. テスト実行で動作確認
7. git commit（feat/fix/chore プレフィックスつき）
8. progress.json を更新する
9. 終了
```

### イテレーション終了時に progress.json へ必ず書くこと
- `last_completed`: 今イテレーションで完了したタスク
- `next_tasks`: 次イテレーションでやるべきタスク
- `blockers`: ブロッカー（なければ空配列）
- `iteration`: イテレーション番号（+1 する）
- `status`: `"in_progress"` or `"done"` or `"blocked"`

## anti-human-bottleneck の原則

**人間に確認を求める前に、以下を試みること：**

| 状況 | 取るべきアクション |
|------|-----------------|
| テストが失敗している | ログを読んで自分でデバッグする |
| APIの仕様がわからない | ドキュメントファイルを読む・コードを読む |
| どのアプローチが良いか迷っている | PROMPT.md のゴールから逆算して決める |
| エラーが解決できない | `blockers` に記録してループを終了（人間にバトンを渡す） |

**人間を巻き込んでよい唯一のケース**: 認証・決済・本番データ変更のコード
