# 実験ルール

## 実験の原則

### 記録なしの実験は禁止
実験を実行したら、成否にかかわらず `result.json` に記録する。
記録のない実験は「存在しない実験」と同じ。

### 本番データへのアクセス禁止
R&D 環境では本番データベースへの接続は禁止。
テストデータ・サンプルデータのみ使用する。

### コスト上限を守る
`PROMPT.md` に記載されたAPI予算上限を超えてはならない。
超えそうな場合は実験を中断してユーザーに報告する。

## result.json の必須フィールド

```json
{
  "exp_id": "EXP-XXX",                    // 必須
  "hypothesis": "仮説の文章",               // 必須
  "status": "success|failed|partial",      // 必須
  "metrics": { "指標名": 値 },             // 数値で記録
  "result": "success|failed|partial",      // 必須
  "learning": "何を学んだか（1文以上）",    // 必須（失敗時は特に重要）
  "next_action": "次に何をするか"          // 必須
}
```

## ガードレール更新のタイミング

以下の場合に CLAUDE.md の「学習済みの禁止事項」に追記する：

1. 同じ種類のミスを 2 回以上犯した
2. 思い込みが実験結果に悪影響を与えた
3. スコープ外に踏み込んで時間を無駄にした

**追記フォーマット:**
```markdown
- {{何をしてはいけないか（具体的に）}} — {{理由（実験番号引用）}}
```

例:
```markdown
- データ拡張なしで learning_rate を下げてはいけない — 小規模データでは過学習が悪化する（EXP-003）
```

## 実験番号の採番ルール

`EXP-001` から始まり連番。
大きな実験の中に小実験を作る場合は `EXP-001/child-001/` の入れ子構造。
