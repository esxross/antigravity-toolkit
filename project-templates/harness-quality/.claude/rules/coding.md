# コーディングルール

## 型安全性
- `any` は使わない。不明な型は `unknown`
- 型アサーション（`as`）は最小限に、必要なら型ガードを使う
- `!`（non-null assertion）は使わない

## エラーハンドリング
- `try/catch` を非同期処理に必ずつける
- エラーは握りつぶさない（最低でも `console.error`）
- カスタムエラークラスで種類を区別する

## 関数・クラス設計
- 1関数1責務
- 純粋関数を優先する（副作用を最小化）
- 早期リターンでネストを浅く保つ

## コメント
- 「何をするか」ではなく「なぜそうするか」を書く
- 自明なコードにコメントは不要
- TODO/FIXME には担当者と期限を書く

## 禁止パターン
- `eval()` の使用
- `innerHTML` への直接代入（XSSリスク）
- `dangerouslySetInnerHTML` の無条件使用
- 同期の `fs` 関数をサーバーのホットパスで使う
